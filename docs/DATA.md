## Unified Admin maintenance coverage and progress

Migration `0020_maintenance_coverage.sql` adds two empty, additive movie relationships. `movie_maintenance_coverage` is keyed by movie/provider/domain (metadata or scores), with authoritative identity provider/ID, successful checked time and JSON absent-field/dimension names. `movie_maintenance_failures` stores only movie/provider/operation and last failed-attempt time; it never establishes a successful negative check. Both cascade on movie deletion. No existing metadata, scores, History, Seen, enrichment or earlier migrations are rewritten and historical blanks remain unchecked.

Coverage distinguishes present, unchecked, successfully checked but unavailable, stale, unidentifiable, unavailable provider and failed/inconclusive evidence. OMDb metadata records a successful identity-bound check even if title/year/runtime/director/genres are unavailable or unchanged. The Repository.enrichOmdbMetadata facade saves this metadata-domain coverage only after the canonical metadata batch succeeds, using normalised null/empty provider fields as absent evidence. Unified individual, combined and incidental score-fallback paths share that facade; callers must not add a second coverage write. Provider, identity or persistence failures cannot advance that check. TMDB canonical metadata and artwork use their independent checked timestamps; both stored TMDB artwork types also establish positive artwork evidence when an older artwork marker is absent. Typed enrichment state is successful complete-response evidence, including empty relationship sets; bounded existence queries count unavailable relationship families without sending cache rows to the browser. Legitimate zero financial values and missing Australian watch offers are successful evidence. Failed/malformed enrichment preserves earlier validated sets and checked times. Legacy cache/title evidence without a successful complete-enrichment state does not fabricate completion.

Populate does not revisit successful negative evidence solely because it is old. Unchecked canonical/provider evidence remains actionable even if some fields already exist. Metadata Populate preserves populated scalar fields and valid genres, subject to the established canonical title resolver. Refresh selects every supported identity in its requested scope regardless of completeness/age. It preserves good scalar/genre values on omissions, retains score snapshots and reconciles validated enrichment sets, including successful empty sets. Score scope is distinct Classics/active History; metadata/enrichment scope is the whole catalogue. Per-provider successful absent-score checks avoid repeating already-conclusive paths while another fallback remains inconclusive. A dimension-level negative still requires all supported identity-applicable paths to succeed; usable persisted live snapshots remain positive evidence.

All individual and aggregate actions use origin-local `bookclub.maintenance.<populate|refresh>.<operation|all>.v1` checkpoints containing version, intent, operation, run start time, pending canonical film/provider identities and operations, and completed count. Accepted provider work is removed independently of failed/unprocessed peers; Stop/navigation preserve the in-flight accepted batch. Explicit resume intersects the frozen scope with current identities/eligibility and successful checks since the run start (including committed work whose response was lost). It adds no new films or responses/keys/personal data. Completion/discard removes the checkpoint; corrupt shapes are rejected and storage denial retains memory-only progress. Existing OMDb and provider-enrichment ID checkpoints migrate to the corresponding Refresh keys. The frontend lock lasts for the entire combined run, but is per mounted Admin and does not coordinate different clients.

Guarded identity merges archive both new tables in their existing receipts and retain latest compatible identity-bound coverage per provider/domain. Wrong-identity repairs archive and discard that identity's coverage/failures; unrelated survivor evidence remains intact. Snapshot copying permits these additive tables to be absent from older exports, leaving them empty rather than seeding historic successful checks.

## Builder draft persistence

Builder uses one in-memory serial/coalescing queue per edited private draft. New set alone does not write; film additions/removals/moves (including inspection-confirmed additions) or changed title/note blur enqueue the latest snapshot. Typing stays local; another persist-worthy action may include current text. Each response advances ID/revision without replacing newer fields, and further queued changes use that revision. Successful saves patch local sets directly; no per-save list reload occurs. Queued new drafts remain available through All sets. Failures retain dirty state and stop automatic retries until another edit or explicit Save set. Save set flushes and returns to the list; The Builder UI enables Use set only for the effective active member’s current human turn (including swaps), with a nonempty lineup. Use set flushes before confirmation and publication and publishes the latest saved revision. Draft/queue state is transient, with no browser storage. Unblurred focused text is the ordinary loss window; failed or pending writes remain unconfirmed until persistence succeeds.

## Identifiers, relationships and ordering

Human positions are `club-member-1` through `club-member-4` in Sean/Troy/Matt/Jess order (sort_order 1–4); names/auth provisioned privately. Provider IDs are aliases. Event order within cycles is nominal slot order, not asserted chronology. Film order follows positive viewing position, including repeated films.

Slot 1 establishes an exact cycle anchor, from its actual first event (normally hosted, exceptionally Classics); later exact event dates never retime it. Imported Tracker Ruff Date is exact only for slot 1; later slots use `cycle_rough` reference because their actual dates are unknown. Explicit slot-1 anchor correction updates only legacy reference dates, including on later restoration, with audit; it does not retime later exact dates or rotation. See [CONTRACTS](CONTRACTS.md#events-rotation-and-history).

New Event entry derives host/kind from the current rotation: effective active human assignment, or hostless Classics at its cycle position (normally 5, exceptionally 1), regardless of viewer or completion. Missing active roster identity fails clearly. Corrections preserve stored historical host/kind, including inactive hosts and historical differences from nominal position. Ordinary Builder publication retains its publisher-host rule. Exceptional-cycle completion resolves the effective rotation identity, including hostless first and hosted final positions; historical Builder publication uses the selected cycle’s stored kind arrangement and publisher host. Editing requires admin or the stored actual host of a hosted event; delete and audit reads require admin. Catalog `has_audit` derives from existing `history_audit` rows without loading audit bodies. Soft deletion frees occupied slots; restoration checks conflicts and requires admin. Correcting/deleting a completed-turn event flags review in audit without silently rewinding rotation.

Native Worker D1 batches atomically combine headers/joins, publication, audits, Builder deletion, rotation and qualifying Seen changes. Builder revision and rotation version guard concurrent updates; History replacement remains last-write-wins. A film in active History is definitive evidence that all active members have Seen it. Every event save (hosted or Classics, including corrections and Builder publication) and restoration upserts Seen=1 for every lineup film and active member in the same atomic batch, replacing earlier No answers. Inactive members are not newly populated. Deletion or lineup correction never reverses Seen evidence because attestation provenance is not distinguished.

## Backup, recovery and local snapshots

`corepack pnpm db:refresh-from-prod` is an explicit one-way current-production read/export and local replacement, not archive replay or production mutation. It needs Node 24+, pnpm execution context and Cloudflare operator login or process-only credentials with D1 read/export rights. CLI requires stopped local API; the confirmed development panel supervises API stop/restart. On Windows, Vite file watchers can hold the local D1 directory open and block replacement with EPERM; stop both the UI and API and use the CLI refresh in that case, then restart them. No arbitrary DB target or remote write option is accepted.

The code verifies the exact configured production name/UUID, exports SQL to ignored temporary storage, restores it offline and stages current local migrations. Source application tables must match, except the precisely enumerated ten additive 0016 provider-cache tables and two additive 0020 coverage/failure tables may be absent from an older source and remain empty in the fresh destination; the three reviewed production identity maintenance tables are also supported and preserved locally. Unknown source tables or columns fail closed. The explicitly reviewed pre-0010 source columns `sessions.title`, `sessions.notes` and `sessions.swap_note` are omitted when absent from the destination, supporting a 0009 snapshot copied into local schema 0012. Copied `history_audit.changes_json` has those same fields removed from `before`/`after`, matching migration 0010. Destination-only columns retain migration defaults/nulls, including `club_rotation.human_order` (`{}`), rotation/cycle `classics_first` (0) and `movies.director` (null). Sanitisation otherwise preserves product rows (including roles, avatars, private Builder, deleted events and audit), empties `auth_sessions`/`provider_cooldowns`, replaces authorised emails with unique `@bookclub.invalid` values and clears Google sub/binding/login timestamps. The demo seed marker prevents fresh demo history entering the snapshot.

Before replacement, per-table counts, SQLite integrity/FKs and actual local-emulator catalog, History, Metrics, Watch Order and per-owner Builder reads must pass. Guards confine filesystem operations to local state; API must be stopped for swap. Prior local D1 is retained at `worker/.wrangler/state/v3/d1-before-refresh-<timestamp>`. Rename failure restores it; supervised Worker-start failure attempts previous-state restore/restart. Retained state is private disposable local data, not a production backup. Local edits never sync upstream.

Restore/copy failures report the stage and, for copy operations, the schema/table/operation with allow-listed SQLite error categories; private SQL, row values and raw upstream messages are suppressed. Raw export is removed on completion/handled failure; a crash may leave ignored private temporary files or `worker/.wrangler/dev-refresh.lock`. Stop processes before inspecting/removing stale files/locks; check resolved paths. CLI reports capture time/counts/rotation. `/__dev/refresh` is a local tooling surface described in [CONTRACTS](CONTRACTS.md#development-refresh-boundary).

The production archive tooling can create timestamped SQL exports with SHA-256/count/target/capture proof before guarded mutation; preserve the original pristine export and independent copy. Export integrity is not a tested restore. No scheduled production backup or general automatic production rollback is implemented. Soft-deleted History has audited admin restoration; this is distinct from whole-database restore.

## Data safety and unknowns

Snapshots still contain private product data after auth sanitisation: do not share/commit them, logs, screenshots or private archive artefacts. Never read/print credential-bearing `OWNER_INFO.md` for setup. Ordinary local commands use `--local --env local`; preview uses its isolated config/state. `db:reset` is explicitly destructive local-only; never use it on production. Never seed generic identities to production.

Live schema/rotation and backup availability cannot be certified from source. Verify them only within the authorised operational task; do not reset production to satisfy historical null-sub/avatar/no-session bootstrap assertions.
